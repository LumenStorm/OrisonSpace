# Orison Space 阶段开发规划

> 本文整合产品化 review、用户痛点与模块规划、CBA 路线图。data-flow-ipc-cleanup 已完成，不再列入。

---

## 产品决策锚点

| 决策项 | 结论 |
|--------|------|
| 产品定位 | 本地优先、BYO API Key、无账号、开源；预留商业化扩展点（付费模型路由、云备份等） |
| 首个用户画像 | 网文/长篇小说作者 |
| Beta 核心闭环 | 项目管理 + 章节编辑 + AI 生成/续写/润色/审阅 + 保存 + 时间线 + 图片生成 + Agent 对话 |
| Auto Mode | 降级为实验功能（Option A），标注 Experimental，不阻塞 Beta |
| 发布平台 | Windows / macOS / Linux 三平台同等优先 |
| 开源治理 | 暂不接受外部贡献，先内部稳定产品 |

## Phase 2: 核心创作闭环验收

**目标：** 验证用户可以完成一次真实创作工作的最小闭环。

### 2.1 核心流程定义

1. 创建或打开本地项目
2. 编辑大纲 / 章节 / 创作字段
3. 配置 OpenAI-compatible 模型
4. 生成、续写、润色或审阅章节候选
5. 用户预览、接受或拒绝 AI 改动
6. 保存到本地项目文件
7. 创建时间线节点并查看 diff
8. 关闭和重启应用后恢复项目和未完成状态

### 2.2 关键路径测试覆盖

- 保存失败必须可见（不吞错误）
- 未保存关闭守卫可靠
- AI 候选接受后落盘路径正确（agent patch 语义）
- 项目注册和最近项目跨重启保持
- 外部文件改动冲突可见

### 2.3 图片生成闭环

- 模型配置 → 图片生成 → temp 落盘 → 画廊浏览 → 确认入库
- 图片编辑（画笔/遮罩/裁切）可用
- 上传参考图编辑模式可用

### 2.4 Agent 对话闭环

- Agent 会话创建 → 消息流式传输 → 工具调用展示 → 确认卡片 → diff 审阅 → 接受/拒绝
- Skill 列表加载 → 手动执行 skill → 结果展示
- Abort 可以终止执行

### 2.5 Release Smoke Test

- 三平台均能完成：打开项目 → 编辑 → 保存 → 重启恢复

### 验收标准

- `pnpm typecheck && pnpm test && pnpm lint` 通过
- 人工执行核心闭环 checklist 通过

**目标：** 用户回到项目时知道当前状态和下一步。

### 6.3 下一步建议

- 快捷入口到编辑、审稿、生图、导出

### 验收标准

- 用户打开项目后 3 秒内理解当前状态

## Phase 7: Agent Workbench（Agent 工作台）

**目标：** 从"能跑"升级为"用户可理解、可控制、可恢复"的完整工作台。

### 7.1 Agent Panel 基础体验

- 消息流式展示
- 工具调用过程可见
- 确认卡片（高风险操作必须确认）
- Diff 审阅（接受/拒绝/部分接受）
- 错误状态和失败提示
- 历史会话浏览

### 7.2 Agent 权限管理

- 工具权限配置
- 高风险操作确认策略
- 最大执行步数 / 嵌套深度
- 失败后行为配置

### 7.3 子代理能力闭合

- `tools` frontmatter 接入真实 tool registry
- `model` frontmatter 接入 model gateway 路由
- 嵌套确认流透传到父会话
- child 事件 UI 从角标升级为可折叠树状过程树

### 7.4 可观测与可恢复

- Agent run 状态：idle / running / waiting / failed / done / aborted
- Abort / retry / restore 入口
- 长任务产物落盘或可恢复
- 运行日志可查看
- 应用重启后用户能知道上次 Agent 做到了哪一步

### 7.5 Auto Mode 重建（独立里程碑，不阻塞 Beta）

- 定义最小稳定场景："对选定章节逐章生成候选，用户逐章确认"
- orchestrationIpc 从内存 Map stub 改为真实 service
- run state 持久化到项目目录或本地 SQLite
- 接入 WorkflowRuntime
- 支持暂停、恢复、取消、失败重试、进度事件
- UI 展示当前章节、当前步骤、失败原因、可恢复操作

### 验收标准

- 用户可以让 Agent 做一次章节审稿，并清楚看到建议和可接受修改
- Agent 失败不会卡住 UI
- 失败后可以重试或安全放弃

## Phase 8: Skills Library（技能库）

**目标：** 支撑方法论复用，让 skill 从散乱 prompt 变成结构化可执行能力。

### 8.1 Skill 管理

- 内置 skills 列表
- 按包启用/禁用
- 来源目录管理
- Skill 权限声明
- Skill 版本管理
- 导入/导出 skill 包

### 8.2 Skill 执行体验

- 执行前摘要：目的、输入、可能修改范围
- 执行过程展示
- 执行后报告：发现、建议、产物、后续动作
- Skill 输出不是纯文本堆叠，而能形成报告、diff 或 structured artifact

### 8.3 Starter Skills（内置起步技能）

- 开篇钩子诊断
- 章节节奏审稿
- 人物一致性检查
- 伏笔种植与回收检查
- 角色图提示词生成
- 封面 brief 生成
- 世界观漏洞检查

### 8.4 Skill 生态规范

- Skill 编写指南
- 目录结构、frontmatter、reference、输入输出、确认点定义
- Skill 质量标准：可解释、可复用、不过度承诺、不绕过用户确认
- Review checklist

### 验收标准

- 用户能从 UI 中找到、理解、运行 skill
- 内置 starter skills 覆盖"写作审稿"和"配图准备"两个方向

### 9.2 世界观系统

### 9.5 标签与引用

## Phase 10: Review Center（审稿中心）

**目标：** 把 AI 从生成器变成审稿伙伴，解决长篇一致性崩坏。

### 10.1 审稿能力

- 章节节奏审稿
- 人物一致性检查
- 世界观冲突检查
- 伏笔回收检查
- 重复表达和语气检查

### 10.2 审稿报告

- 结构化审稿报告输出
- 问题定位到具体段落/章节
- 严重程度分级

### 10.3 可接受 Patch

- 审稿建议可转化为 diff patch
- 用户可逐条接受/拒绝/修改
- 接受后正确落盘

### 10.4 章节摘要和长期记忆

- 章节摘要自动生成
- 长期记忆抽取和维护
- 上下文构建策略（摘要、记忆、检索、用户可控引用范围）

### 验收标准

- 审稿工具能指出明显一致性风险
- 审稿建议可直接转化为修改操作

### 11.3 素材库

- 素材库元数据
- 图片编辑和入库确认
- 支持生成、编辑、确认入库、替换、删除

### 验收标准

- 用户知道一张图来自哪个角色/场景/章节
- 同一角色可以复用外观描述和风格约束

## Phase 12: Export Center（导出中心）

**目标：** 让作品离开应用也成立，闭合创作最后一环。

### 12.1 DOCX 导出

- 章节正文 + 标题层级 + 目录 + 作者信息 + 章节顺序
- 模板：网文投稿、内部审阅、实体书草稿
- 选择导出范围：全书、分卷、选中章节

### 12.2 PDF 导出

- 基于模板排版 + 页眉页脚 + 页码 + 目录
- 中文字体 fallback 或嵌入
- 审阅版和阅读版

### 12.3 EPUB / HTML（评估后决定）

- 评估是否进入 1.0 范围
- 基础章节导航和元数据
- 若不进入范围，不提前承诺

### 12.4 作品导出包

- 正文 + 素材图 + 项目元数据 + 审稿摘要
- 可选创作档案：版本节点、主要修改说明、角色表
- 封面和插图位置

### 验收标准

- 导出的 DOCX/PDF 可被 Word/WPS/PDF 阅读器正常打开
- 标题、段落、目录和章节顺序正确，中文不乱码

## Phase 13: Workflow 模板

**目标：** 将 C 阶段方法论转化为可运行、可审阅、可复用的自动化工作流。

### 13.1 章节审稿 Workflow

- 读章节 → 读设定 → 输出问题 → 给出 patch → 用户确认

### 13.2 角色一致性 Workflow

- 读人物卡 → 扫章节 → 找冲突 → 给出建议

### 13.3 配图准备 Workflow

- 读角色/场景 → 生成 image brief → 调图像模型或入队

### 13.4 伏笔 Workflow

- 种植、追踪、回收、遗漏提示

### 验收标准

- Workflow 可复用方法论文档
- 每个可写操作都有用户确认或可回滚机制

## Phase 14: 质量门禁升级

**目标：** 从 warning 记录升级为产品级回归阻断。

### 14.1 IPC 边界收口

- features/store 中直接访问 `window.orisonDesktop` 统一走 `shared/api/*.ts`
- 清零后升为 error

### 14.2 dependency-cruiser warning 清零

- 清理 shared → features 倒置和循环依赖
- 清零后升为 error

### 14.3 workspace lint 脚本实体化

- 替换各 package 中 `echo ... lint placeholder`

### 14.4 i18n 裸文本分批迁移

- 用户可见 JSX 文本逐步迁移到 zh-CN / en-US YAML

### 14.5 死代码和依赖审计

- `pnpm deadcode` 定期检查
- Beta 前跑一次依赖安全和许可证审计

### 验收标准

- `pnpm lint` warning 总数只降不升
- 关键边界规则升为 error 后 CI 通过

### 15.4 发布回滚策略

**目标：** 让用户能学会产品，为社区开放打基础。

### 16.1 用户快速开始

- 安装 → 创建项目 → 配置模型 → 写第一章 → 接受 AI → 保存版本

### 16.2 数据与隐私说明

## 里程碑对照

| 里程碑 | 对应 Phase | 标志 |
|--------|-----------|------|
| Trustworthy Alpha | 1 | README 可信、版本一致、实验功能标注 |
| Reliable Creative Loop | 2 | 核心闭环人工验收通过 |
| Settings & Trust | 3-4 | 设置中心骨架完整、备份恢复可用 |
| Onboarding & Dashboard | 5-6 | 新手引导和项目仪表盘可用 |
| Agent Workbench | 7 | Agent 可理解、可控、可恢复 |
| Skills Ecosystem | 8 | Skill 管理 + starter skills 可用 |
| Creative Assets | 9-10 | 资产中心 + 审稿中心可用 |
| Visual & Export | 11-12 | 配图闭环 + 导出可用 |
| Automation | 13 | Workflow 模板稳定 |
| Beta Release | 14-15 | 质量门禁升级 + 三平台发布 |
| Product Docs | 16 | 用户文档 + 方法论 + 示例项目 |

## Non-Goals

- 不引入远程账号系统作为默认路径
- 不重建云同步
- 不重做 UI 视觉风格
- 不一次性完成 Auto Mode 全部愿景
- 不在质量门禁升级前扩大功能面
- 不把配图做成和小说项目无关的普通图库
- 不让 AI 自动覆盖用户稿件
- 不把设置中心变成复杂后台管理系统
